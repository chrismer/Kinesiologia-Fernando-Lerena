Sistema de gestión para el consultorio.

Aplicación de escritorio Windows para administrar pacientes, turnos, agenda y evoluciones clínicas de kinesiología. Pensada para recepción, kinesiólogos y administración, con PostgreSQL en la nube y un modo offline para desarrollo.

Recorrido del sistema en C# / Windows Forms: login, pacientes, turnos, agenda y consulta activa.

Qué resuelve

El consultorio necesita ver el día, ubicar un paciente, atender un turno y dejar registrada la sesión. El sistema concentra esas tareas en una sola ventana principal, con menú lateral y pantallas incrustadas en un panel.

Si no hay appsettings.json con conexión, arranca con repositorios en memoria (un paciente demo). Con Neon configurado, trabaja contra la base real.

Login

Primera pantalla. Valida usuario y clave (BCrypt). Cancelar o cerrar termina la app.

Pantallas

Cada captura es una pantalla distinta del escritorio. Clic para ampliar.

Dashboard Pacientes Ficha Consulta Turnos Agenda Configuración

Dashboard

Turnos del día, contador de atendidos, próximo turno, Ver detalles y Marcar como llegado.

Pacientes

Listado con búsqueda en vivo por nombre, apellido o DNI. Ver Detalle abre la ficha. Atender Paciente abre consulta sin turno.

Ficha del paciente

Modal demográfico: dirección, teléfonos, email, obra social, plan y observaciones. Sin historial de evoluciones. Ir a Consulta abre la atención.

Consulta activa

Historial a la izquierda. A la derecha: EVA 0–10, técnicas (magnetoterapia, ultrasonido, terapia manual, ejercicio) y notas. Guardar exige comentario.

Turnos

Filtro por fechas, profesional, estado y paciente. Grilla de fecha, hora, cobertura, diagnóstico y estado.

Agenda

Vistas día, semana y mes. Color por profesional. Calendario a la izquierda y grilla horaria a la derecha.

Configuración

Solo admin. Alta, foto/clave, permisos y baja lógica de usuarios. Recepción y kinesiólogos no ven este menú.

Roles

El login valida usuario y clave (BCrypt). El kinesiólogo queda ligado a un profesional; admin y recepción no.

RolVeRestricción
admin Todo el consultorio y Configuración Alta y baja de usuarios
recepcion Dashboard, pacientes, turnos y agenda de todos Sin Configuración
kinesiologo Sus turnos; historial completo del paciente La evolución se firma con su nombre e id

Usuarios de práctica en sql/005_seed_usuarios.sql y admin en sql/006_usuario_nombre_foto.sql. Clave compartida de desarrollo: no usar fuera de la práctica.

Flujos de trabajo

Atender un turno del día

1
Entrar con usuario y clave. Se abre el Dashboard.
2
Marcar llegada cuando el paciente está en sala.
3
Atender abre la consulta con el turnoId. Al guardar, el turno pasa a Atendido.
4
Registrar EVA, técnicas y comentarios. El kinesiólogo logueado firma la sesión.

Consultar un paciente sin turno

Pacientes → buscar → doble clic o Ver detalle (ficha demográfica y cobertura, sin historial) → Atender abre consulta con turnoId = null. Es una evolución suelta. Abrir la consulta reemplaza el listado en el panel.

Estados de turno: Pendiente, Presente, Atendido (tiene evolución), Ausente. El dashboard y Turnos usan ese cálculo, no un campo suelto.

Decoradores de sesión

Si el rol es kinesiólogo, TurnoRepositoryPorSesion filtra sus turnos y EvolucionRepositoryPorSesion firma cada evolución nueva. El historial del paciente sigue siendo de toda la clínica.

Cómo arrancarlo

  1. Copiar appsettings.example.json a appsettings.json y completar Neon, o dejarlo sin archivo para modo memoria.
  2. Correr los scripts sql/001 a sql/006 en ese orden.
  3. Abrir TESTSOLAPAS.slnx y ejecutar.
"ConnectionStrings": {
  "Kinesiologia": "Host=...neon.tech;Database=kinesiologia;SSL Mode=Require;..."
}
Sin conexión, Pacientes muestra un único paciente demo. El listado completo aparece solo con la base sembrada.
